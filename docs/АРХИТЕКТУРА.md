# Архитектура ConstructionProjects

Документ фиксирует стек, структуру проекта и соглашения. Требования к
функциональности — в `ТЗ.md`.

## 1. Стек и обоснование

| Слой | Выбор | Почему |
|---|---|---|
| Каркас | Next.js 15, App Router | Один проект вместо пары «фронтенд + API». Server actions убирают ручной слой REST-эндпоинтов для форм. Серверный рендеринг даёт быстрые тяжёлые реестры |
| Язык | TypeScript, режим `strict` | Типы схемы Prisma доходят до компонентов без ручного дублирования |
| База | PostgreSQL 16 | Оконные функции и агрегаты для будущего дашборда, тип `jsonb` для журнала изменений, честный `Decimal` для денег |
| ORM | Prisma | Типобезопасные запросы, версионируемые миграции, читаемая схема как документация модели |
| Стили | Tailwind CSS | Скорость вёрстки без разрастания CSS-файлов |
| Компоненты | shadcn/ui (Radix) | Код компонентов лежит в репозитории и правится под себя; доступность «из коробки» |
| Таблицы | TanStack Table | Серверная сортировка и пагинация, фиксированные колонки, большие объёмы строк |
| Формы | react-hook-form + Zod | Одна схема валидации работает и на клиенте, и на сервере |
| Локализация | next-intl | Русский сейчас, английский и украинский без переписывания компонентов |
| Графики | Recharts | Понадобится на этапе дашборда; закладывается сразу, чтобы не менять стек позже |
| Excel | ExcelJS | Чтение для импорта и запись для выгрузки одной библиотекой, поддержка форматов ячеек |
| PDF | `@react-pdf/renderer` | Вёрстка отчёта на React, подключение кириллических шрифтов |
| Пароли | `@node-rs/argon2` | Argon2id — актуальная рекомендация OWASP, нативная скорость |
| Тесты | Vitest + Playwright | Модульные тесты прав и аудита; сквозные — на вход и работу с реестром |

Стек закрыт. Новая библиотека добавляется, только если задачу нельзя решить
имеющимися — с обоснованием в pull request.

## 3. Соглашения

### 3.1 Чтение и запись

- `queries.ts` — только чтение, возвращает данные для серверных компонентов.
- `actions.ts` — только мутации, помечены `"use server"`.
- Компоненты не обращаются к Prisma напрямую. Единственная точка входа к базе —
  `src/lib/db.ts`.

### 3.2 Каждый server action устроен одинаково

```ts
export const updateUser = authorizedAction(
  "users.update",                                   // 1–2. кто действует и имеет ли право
  async (actor, id: string, input: unknown) => {
    const parsed = updateUserSchema.safeParse(input); // 3. валидация
    // 4. запись + аудит в одной транзакции
    // 5. revalidatePath
  },
);
```

Порядок обязателен. Проверка прав идёт до валидации: чужому не следует сообщать,
что именно не так с данными, к которым у него нет доступа. `authorizedAction`
(`src/lib/auth/authorized-action.ts`) определяет пользователя и проверяет право
до вызова тела действия, поэтому пропустить эти шаги нельзя; отказ в праве
возвращается результатом, как и остальные ожидаемые ошибки (п. 3.3).

### 3.3 Ошибки

Ожидаемые ошибки (занятый логин, неверный пароль, нарушение правила) возвращаются
как результат: `{ ok: false, error: "users.loginTaken" }`, где значение — ключ
перевода. Исключения бросаются только на непредвиденных сбоях и приводят к
странице ошибки.

### 3.4 Состояние реестров

Поиск, фильтры, сортировка и номер страницы живут в параметрах URL, а не в
состоянии React. Это даёт работающие ссылки, кнопку «назад» и упрощает выгрузку —
экспорт получает те же параметры и отдаёт ровно то, что видит пользователь.

### 3.5 Тексты

Ни одной русской строки в коде. Ключи в `messages/ru.json` группируются по фичам:
`users.form.login`, `auth.errors.invalidCredentials`. Английский и украинский
добавляются копированием файла — структура ключей меняться не должна.

### 3.6 Именование в базе

Модели Prisma — единственное число в PascalCase (`User`, `AuditLog`), поля —
camelCase. Перечисления — SCREAMING_SNAKE_CASE.

## 4. Аутентификация

Применяется схема с непрозрачным токеном и таблицей сессий (подход Lucia),
а не JWT.

Причина: по ТЗ администратор обязан **немедленно** прекращать доступ
деактивированного сотрудника. Подписанный токен нельзя отозвать до истечения
срока, а проверка в базе на каждом запросе сводит на нет его единственное
преимущество. Таблица сессий сразу даёт и отзыв доступа, и экран «Активные
сессии», требуемый ТЗ.

Механика:

1. При входе генерируется случайный токен (32 байта), в базе хранится его хэш.
2. Токен кладётся в httpOnly-cookie `session` с `SameSite=Lax`, срок — 12 часов.
3. На каждом запросе `middleware.ts` проверяет наличие cookie и перенаправляет
   неавторизованных на `/login`; серверная проверка самой сессии и роли
   выполняется в `requireUser()` — middleware к базе не обращается.
   Если cookie есть, а сессия отозвана или истекла, страница перенаправляет на
   `/api/auth/clear-session`: Server Components не могут менять cookie, поэтому её
   удаляет route handler и уже он ведёт на `/login`. Server actions вызывают
   `requireActionUser()` и удаляют cookie сами: цель редиректа из action Next.js
   рендерит на сервере, и cookie из промежуточного ответа до браузера не дошла бы.
4. Сессия с активностью в последний час продлевается автоматически.
5. Деактивация пользователя и сброс его пароля администратором отзывают сессии.

Защита от подделки межсайтовых запросов обеспечивается механизмом server actions
Next.js и флагом `SameSite`; отдельный слой не вводится.

## 5. Экспорт

Единый модуль `src/lib/export` принимает описание колонок и набор данных:

```ts
type ExportColumn<T> = {
  key: keyof T;
  header: string;                      // уже переведённый заголовок
  width?: number;
  format?: "text" | "number" | "money" | "date" | "datetime";
};
```

На вход подаются те же параметры фильтрации, что и у реестра, поэтому выгрузка
всегда соответствует тому, что пользователь видит на экране. Три формата —
`xlsx`, `pdf`, представление для печати — реализуются поверх одного описания.
Разделы следующих этапов подключают экспорт, лишь описав свои колонки.

## 6. Локальный запуск

```bash
cp .env.example .env          # задать POSTGRES_PASSWORD и SEED_ADMIN_PASSWORD
docker compose up -d db       # PostgreSQL 16 на порту 5432
npm install
npx prisma migrate dev        # схема и миграции
npm run db:seed               # первый администратор
npm run dev                   # http://localhost:3000
```

Сид создаёт единственную учётную запись `admin` с паролем из переменной
`SEED_ADMIN_PASSWORD`. Пароля по умолчанию в коде нет — при незаданной переменной сид завершается
с ошибкой.

**Скрипты:** `dev`, `build`, `start`, `lint`, `typecheck`, `test`, `test:e2e`,
`db:seed`, `db:studio`.

## 7. Что должно оставаться расширяемым

Решения этапа 1, на которые обопрутся следующие разделы, — менять их потом дорого:

1. **Аудит** — универсален по типу сущности (`entity` + `entityId`), поэтому
   проекты и сметы подключаются без изменения таблицы.
2. **Права** — заданы строками вида `users.update`; добавление раздела означает
   добавление строк в матрицу, а не переписывание проверок.
3. **Экспорт** — работает с описанием колонок, а не с конкретной моделью.
4. **Локализация** — все тексты вынесены с самого начала.
5. **Поля аудита в таблицах** — `createdById` и `updatedById` заводятся сразу
   в каждой новой модели, иначе отметку «кем изменено» придётся добавлять
   задним числом по всей базе.
